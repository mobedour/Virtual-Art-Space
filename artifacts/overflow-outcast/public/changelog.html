The Big Picture

This is a monorepo — one repository containing multiple applications and shared libraries, all managed together by pnpm workspaces. Think of it like one building with separate floors, each doing a different job but sharing a basement of common utilities.

Root Level — the lobby

  • pnpm-workspace.yaml — Tells pnpm which packages live in this repo (artifacts/*, lib/*, scripts). Also pins shared dependency versions so every package uses the same version of React, TypeScript, etc.
  • package.json — Root-level scripts that run across the whole project: pnpm run typecheck (check all TypeScript), pnpm run build (build everything for deployment)
  • tsconfig.base.json — Shared TypeScript rules inherited by all packages: strictness settings, target, module format
  • tsconfig.json — The "solution file" — tells TypeScript which shared libraries to compile first, in the right order, before checking the apps
  • replit.md — The project's memory: stack, architecture decisions, roadmap, and preferences. The live content above is pulled directly from this file.

lib/ — Shared Libraries (the basement)

These packages are used by both the frontend and backend. You never run them directly — they're built and imported by the apps.

lib/api-spec/

The single source of truth for the entire API.

  • openapi.yaml — Describes every API endpoint: URL, method (GET/POST/etc.), what data goes in, what comes out, and which routes require login. This one file drives code generation for both the frontend and backend.
  • orval.config.ts — Config for the code generator. Running pnpm --filter @workspace/api-spec run codegen reads the YAML and auto-generates the frontend hooks and backend validators below.

lib/api-zod/

Auto-generated — never edit manually. Zod validation schemas for every data entity (Gallery, Artwork, User, Profile). The API server imports these to validate that incoming data matches the expected shape before touching the database.

lib/api-client-react/

Auto-generated — never edit manually.

  • src/generated/api.ts — React Query hooks: useGetGalleries, usePostArtwork, useGetProfile, etc. The frontend imports these and they handle loading states, caching, and re-fetching automatically.
  • src/custom-fetch.ts — The underlying fetch function used by all hooks. This is where auth tokens get attached to every API request — reads the token from Clerk and adds it as a Bearer header automatically.

lib/db/

The database layer.

  • src/schema/users.ts — Platform users table, linked to Clerk identities
  • src/schema/profiles.ts — Artist display info: bio, avatar, social links
  • src/schema/galleries.ts — Gallery rooms: title, slug, theme, published status
  • src/schema/artworks.ts — Individual pieces inside galleries: title, image, dimensions, description
  • src/index.ts — Creates the database connection and exports the db object that all routes use to query data

artifacts/ — The Applications

artifacts/api-server/ — The Backend

The Express server. Runs at port 8080 and handles all data. It's what the frontend talks to.

  • build.mjs — esbuild script that bundles the TypeScript server into a single dist/index.mjs for production
  • src/index.ts — Starts the HTTP server, binds to the port
  • src/app.ts — Sets up Express: attaches Clerk auth, Pino logger, CORS, JSON parsing, then mounts all route handlers

Middlewares:

  • src/middlewares/requireAuth.ts — Protects private routes. Reads and verifies the Clerk JWT. On first login, automatically creates a local database user (JIT provisioning). Handles the edge case where a Clerk email already exists in the DB.
  • src/middlewares/clerkProxyMiddleware.ts — Makes Clerk auth work correctly behind Replit's proxy layer

Routes:

  • routes/index.ts — Mounts all route files under their URL prefixes
  • routes/auth.ts — /api/auth/me: returns the current logged-in user's info
  • routes/profile.ts — GET/PATCH /api/profile: view and edit your artist profile
  • routes/galleries.ts — Full CRUD for your own galleries: create, list, edit, delete, publish
  • routes/artworks.ts — Full CRUD for artworks within a gallery
  • routes/publicGalleries.ts — Public browsing: anyone can view published galleries without logging in
  • routes/dashboard.ts — /api/dashboard/stats: counts for the artist dashboard (galleries, artworks, views)
  • routes/changelog.ts — Serves this progress page's content live from replit.md via SSE stream
  • routes/health.ts — /api/healthz: simple ping for deployment health checks

artifacts/overflow-outcast/ — The Frontend

The main React app. Everything visual lives here.

  • index.html — The HTML shell that loads the React app
  • src/main.tsx — Bootstraps React, wraps everything in Clerk's auth provider and React Query's data provider
  • src/App.tsx — Root component: sets up routing, mounts ClerkAuthSync (registers token getter so every API call gets auth headers), renders pages

Pages:

  • home.tsx — Public landing page: hero, feature highlights, browse galleries
  • galleries.tsx — Artist's private gallery management dashboard
  • gallery-form.tsx — Create or edit a gallery: name, description, theme picker
  • artworks.tsx — Manage artworks inside a specific gallery
  • artwork-form.tsx — Upload or edit an artwork: image, title, dimensions, description
  • public-galleries.tsx — Public browsing: all published galleries from all artists
  • public-gallery-detail.tsx — The 3D gallery room viewer for a published gallery
  • profile.tsx — Edit your own artist profile
  • dashboard.tsx — Artist stats overview

3D Gallery Room (src/components/gallery-room/):

  • GalleryRoom.tsx — Top-level wrapper: handles loading state, fetches gallery + artworks, renders the scene or a loading screen
  • GalleryScene.tsx — The actual 3D room in React Three Fiber. Renders floor, ceiling, walls, lighting, places artwork frames. Handles mouse look, WASD movement, and pointer lock.
  • ArtworkFrame.tsx — A single framed artwork on the wall: 3D mesh with image texture, frame geometry, label plate. Emits a click event to open the detail modal.
  • ArtworkDetailModal.tsx — The overlay when you click an artwork: full image, title, dimensions, description. Responsive for mobile landscape.
  • RoomDecorations.tsx — Non-artwork 3D elements: spotlights, pedestals, ambient decorations based on the active theme
  • TouchControls.tsx — Mobile movement: detects touch, handles virtual joystick and swipe-to-look
  • VirtualJoystick.tsx — The on-screen joystick UI for mobile walking
  • theme-config.ts — Defines the 5 room themes (Dark Void, Neon Grid, Concrete, etc.): colors, lighting, materials, fog settings
  • room-dimensions.ts — Constants for the room's physical size, wall positions, and artwork slot positions
  • seeded-rng.ts — Deterministic random number generator: ensures artwork placement looks identical every time you load a gallery (same seed = same layout)

Shared components:

  • layout.tsx — Authenticated app shell with top navbar and user avatar
  • public-layout.tsx — Public-facing shell with simpler navbar for unauthenticated visitors
  • GalleryThumbnail.tsx — The gallery card in list views: thumbnail, title, artwork count, theme badge
  • components/ui/ — ~40 reusable UI primitives (buttons, dialogs, inputs, tabs, toasts, etc.) based on shadcn/ui

Public files (public/):

  • changelog.html — This page: client-facing project progress (standalone HTML, no React)
  • invoice.html — Project invoice document
  • favicon.svg / logo.svg — Brand assets
  • opengraph.jpg — Preview image when sharing the site link on social media
  • robots.txt — Tells search engine crawlers what to index
  • images/ — 6 Amman reference photos used as placeholder artwork in seed data

artifacts/mockup-sandbox/ — Design Prototyping

A completely separate Vite app used only for designing and previewing new UI components before building them into the real app. Powers the Canvas board previews.

  • mockupPreviewPlugin.ts — Custom Vite plugin that auto-scans src/components/mockups/ and registers every component it finds for isolated preview at /__mockup
  • src/components/mockups/amman-homepage/ScrollingHome.tsx — The scrolling homepage mockup on the canvas board
  • src/components/ui/ — shadcn UI kit mirrored here so mockups can use it

scripts/ — Utility Scripts

  • src/seed.ts — Populates the database with demo content: Amman-themed artists, galleries with Arabic/contemporary art metadata, and artworks using the reference images. Run once to get realistic-looking data for development.

How Everything Connects

The key discipline of this project is contract-first: the OpenAPI spec is the agreement between frontend and backend, and the code on both sides is generated from it — so they can never fall out of sync.

  1. Edit lib/api-spec/openapi.yaml to define or change an endpoint
  2. Run codegen → auto-updates api-zod (validators) and api-client-react (hooks)
  3. api-server uses api-zod to validate requests → queries lib/db → PostgreSQL
  4. overflow-outcast uses api-client-react hooks → renders UI → 3D room
